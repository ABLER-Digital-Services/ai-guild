# 基盤概要設計_バックアップ・リカバリ編スキル

システムを構成するすべてのデータ・リソースについて、「バックアップ取得 → 保管 → リストア」の全体設計を定義するドキュメントを作成・更新する。
バックアップ対象ごとに方式・ツール・頻度・世代数・保管場所・保管期間を明確にし、RTO/RPO 目標を達成するリストア手順と DR シナリオへの対応方針を規定する。

- 「バックアップ設計書を作って」「基盤概要設計_バックアップ・リカバリ編を作って」と言われたとき

- 「RTO/RPO 要件を定義して」「リストア手順を整理して」と言われたとき
- 「AWS Backup の設計を書いて」「RDS スナップショット設計を書いて」「EBS スナップショット設計を書いて」と言われたとき
- 「バックアップ保管期間を定義して」「クロスリージョンバックアップを設計して」と言われたとき

## MECE 章構成の設計思想

バックアップ・リカバリ設計を「データが壊れたときに戻せるまでの全ライフサイクル」に沿って分解することで MECE を実現する。

```
1. 設計方針・前提条件          ← なぜこの設計か、誰が管理するか、制約は何か（Why/Who）
2. バックアップ対象一覧        ← 何をバックアップするか（What/棚卸し）
3. 対象別バックアップ設計      ← どうバックアップするか（How/方式・ツール・頻度）
4. バックアップ保管設計        ← どこにどれだけ保管するか（Where/期間・暗号化）
5. リストア設計                ← どう復元するか（How to Recover/手順・RTO/RPO）
6. DR（障害復旧）設計          ← 大規模障害時の対応シナリオ（Disaster Scenarios）
7. バックアップ検証設計        ← バックアップが正常かどう確認するか（Verification）
8. 運用・コスト管理設計        ← 日常的にどう管理するか（Ops/コスト最適化）
```

**MECE の根拠:**
- 2（何をバックアップするか）≠ 3（どうバックアップするか）: 対象の棚卸しと方式設計は独立した作業
- 3（方式）≠ 4（保管）: バックアップの取得方法と保管場所・期間は別の関心事
- 4（保管）≠ 5（リストア）: 保管は「どこに置くか」、リストアは「どう戻すか」
- 5（リストア手順）≠ 6（DR）: リストアは個別対象の復旧手順、DR は AZ/リージョン障害・データ破損等の大規模シナリオ対応
- 6（DR シナリオ）≠ 7（検証）: DR はシナリオ定義、検証は定期テスト計画と実施手順
- 7（検証）≠ 8（運用）: 検証は「バックアップの正常性確認」、運用は「モニタリング・コスト管理・手順書整備」

## 作成ワークフロー

### Step 1: テンプレートをコピーして成果物を作成

例として、`templates/基盤概要設計_バックアップ・リカバリ編_template.md` を
`docs/01_要件定義/02_非機能/11_バックアップ・リカバリ/基盤概要設計_バックアップ・リカバリ編.md` にコピーして作業を開始する。

既存ファイルがある場合は上書きせず、差分を確認してから追記・修正する。

### Step 2: 関連ドキュメントの参照

以下のドキュメントを事前に参照し、設計の一貫性を確保する：

| ドキュメント | 参照目的 |
|---|---|
| `01_非機能要求グレード.md` | バックアップ頻度・保管期間・RTO/RPO 目標値・準拠法令の確認 |
| `基盤概要設計_クラウドサービス編.md` | 利用 AWS サービス・AWSアカウント設計・AWS Backup 利用有無 |
| `基盤概要設計_ストレージ編.md` | バックアップ対象となるストレージ種別・サイズ・配置場所の確認 |
| `基盤概要設計_データベース編.md` | RDS エンジン・バックアップウィンドウ・PITR 有効化設定の確認 |
| `基盤概要設計_サーバ編.md` | EBS ボリューム構成・バックアップ世代数・スケジュールの確認 |
| `基盤概要設計_セキュリティ編.md` | バックアップデータの暗号化要件・アクセス制御要件の確認 |

### Step 3: ユーザーへのヒアリング

以下の観点でシステムの要件を確認する：

**バックアップ対象の確認**
- バックアップが必要なデータ種別（RDS データ / EBS ボリューム / S3 / アプリケーション設定 / パラメータ設定 等）
- バックアップ対象から除外してよいデータ（一時ファイル・キャッシュ・ログファイル等）
- マネージドサービスを利用する場合、ベンダーがバックアップを管理している対象の有無

**RTO/RPO 要件の確認**
- RTO（目標復旧時間）: 障害発生から何時間以内に復旧すべきか
- RPO（目標復旧時点）: 障害発生時に何時間前の状態まで失ってよいか（例: 24 時間前）
- データ種別ごとに RTO/RPO が異なる場合はそれぞれ確認する

**バックアップ方式・頻度の確認**
- フルバックアップ・増分バックアップの組み合わせ方針
- 自動バックアップの実行スケジュール（日次 / 週次 / 月次の組み合わせ）
- ポイントインタイムリカバリ（PITR）の必要性（特に RDS）
- アプリケーション整合性のあるスナップショットの必要性（VSS / DB フリーズ等）

**バックアップ保管期間・世代数の確認**
- 遵守すべき法令・ガイドライン（犯収法 7年 / 個人情報保護法 / PCI DSS 等）
- RFP・運用ポリシーで指定されたバックアップ保管期間
- 世代数の制約（マネージドサービス利用時のプラットフォーム制限 等）
- クロスリージョン保管の要否（DR 対応 / 法令対応）

**リストア要件の確認**
- リストアの実行主体（お客様自身 / ベンダーへ申請 / 共同対応）
- 部分リストアの要否（個別ファイル / 特定テーブル / 特定期間のデータ）
- リストア後の動作確認手順（アプリケーション起動確認・データ整合性チェック等）
- リストア実施時のダウンタイム許容範囲

**DR・障害シナリオの確認**
- 対象とする障害シナリオ（AZ 障害 / リージョン障害 / データ誤削除 / ランサムウェア等）
- DR サイトの要否（別リージョン / 別 AZ）
- データ誤削除・論理破壊への対応要件（S3 バージョニング / Object Lock 等）

**バックアップ検証の確認**
- リストアテストの実施頻度（月次 / 四半期 / 年次）
- テスト環境でのリストア確認の可否
- バックアップ成功・失敗の通知先と通知手段

### Step 4: 各セクションの記述

テンプレートのプレースホルダーをヒアリング結果に基づいて埋める。

記述の基本スタイル:
- バックアップ対象ごとに方式・ツール・頻度・世代数・保管先・保管期間を表形式で整理する
- 保管期間には根拠（法令要件 / RFP / 運用要件）を明記する
- マネージドサービスで管理される項目は「お客様が設定できる範囲」と明確に区別する
- RTO/RPO は数値で明示し、リストア手順と紐づけて記述する
- 未確定・要調査項目は `> **TODO:**` でマーク

記述例:

```markdown
### RDS（PostgreSQL）

| 項目 | 内容 |
|---|---|
| バックアップ方式 | 自動バックアップ（AWS Backup）+ PITR |
| バックアップツール | AWS Backup / RDS 自動バックアップ |
| フルバックアップ頻度 | 1日1回（毎日 02:00–03:00 UTC）|
| PITR 保持期間 | 7日間 |
| 保管先 | S3（AWS Backup 管理バケット）|
| 保管期間 | 30日（日次スナップショット）/ 1年（月次スナップショット）|
| 暗号化 | AWS KMS （CMK）で暗号化 |
| リストア所要時間目安 | 約 30 分〜1時間（DB サイズによる）|
| 管理責任 | AWS Backup ポリシーの設定: お客様管理 |
```

### Step 5: レビューチェック

- [ ] すべてのバックアップ対象（RDS / EBS / S3 / アプリ設定 / OS・MW 設定等）が対象一覧に列挙されているか
- [ ] 各バックアップ対象に RPO 目標と整合したバックアップ頻度が設定されているか
- [ ] 各バックアップ対象に保管期間と根拠（法令 / RFP / 運用要件）が記載されているか
- [ ] 非機能要求グレードの RTO/RPO 要件と整合しているか
- [ ] リストア手順が対象ごとに定義され、RTO 目標内で完了可能か
- [ ] バックアップデータの暗号化方式が定義されているか
- [ ] クロスリージョン保管の要否が検討されているか
- [ ] データ誤削除・論理破壊への対策（S3 バージョニング / Object Lock / PITR 等）が定義されているか
- [ ] バックアップ成功・失敗の監視・通知が定義されているか
- [ ] 定期的なリストアテストの計画が記述されているか
- [ ] マネージドサービスを利用する場合、ベンダーの制約（世代数上限・リストア申請フロー等）と整合しているか
- [ ] バックアップ保管コストの見積もり・最適化方針が記述されているか

## テンプレートの構成

テンプレート（`templates/基盤概要設計_バックアップ・リカバリ編_template.md`）は以下のセクションで構成される：

| # | セクション | 主な内容 |
|---|---|---|
| 1 | 設計方針・前提条件 | 設計方針・管理責任区分・RTO/RPO 目標値・準拠法令 |
| 2 | バックアップ対象一覧 | 対象名・種別・バックアップ方式・頻度・保管期間の一覧表 |
| 3 | 対象別バックアップ設計 | RDS / EBS / S3 / アプリ設定 / OS・MW 設定の個別設計 |
| 4 | バックアップ保管設計 | 保管先（S3）設計・ライフサイクルポリシー・暗号化・クロスリージョン |
| 5 | リストア設計 | 対象別のリストア手順・所要時間・動作確認チェックリスト |
| 6 | DR（障害復旧）設計 | 障害シナリオ一覧・シナリオ別対応方針・復旧フロー |
| 7 | バックアップ検証設計 | リストアテスト計画・検証手順・結果記録フォーマット |
| 8 | 運用・コスト管理設計 | 監視・アラート設計・コスト見積もり・最適化方針 |
