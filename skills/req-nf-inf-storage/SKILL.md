# ストレージ設計書スキル

システムのストレージ構成（EBSボリューム・RDSストレージ・S3・アプリケーションストレージ等）を定義するドキュメントを作成・更新する。
データ配置方針・各ストレージの用途とサイズ・暗号化・アクセス制御・バックアップ設計・容量増設計画を網羅する。

## When to Use This Skill

- 「ストレージ設計書を作って」「基盤概要設計_ストレージ編を作って」と言われたとき
- 「ストレージを整理して」「データ配置方針を定義して」「ボリューム設計を書いて」と言われたとき
- 「S3設計を書いて」「バックアップ設計を書いて」「容量計画を立てて」と言われたとき
- 既存のストレージ設計書をレビュー・更新するとき

## 成果物の仕様

以下の格納先・ファイル名・多重作成可否は説明用の例です。実際の配置ルールは対象リポジトリ側の instructions、CONTRIBUTING、README などに従ってください。

## 作成ワークフロー

### Step 1: テンプレートをコピーして成果物を作成

例として、`templates/基盤概要設計_ストレージ編_template.md` を
`docs/01_要件定義/02_非機能/05_ストレージ/基盤概要設計_ストレージ編.md` にコピーして作業を開始する。

既存ファイルがある場合は上書きせず、差分を確認してから追記・修正する。

### Step 2: 関連ドキュメントを参照して前提を把握する

以下のドキュメントが存在する場合は先に参照し、ストレージ設計の前提を確認する：

| 参照先 | 確認ポイント |
|---|---|
| `03_クラウドサービス/基盤概要設計_クラウドサービス編.md` | 利用するAWSサービス・各ボリュームのサイズ定義 |
| `04_サーバ/基盤概要設計_サーバ編.md` | 各サーバのディスク構成（ボリューム名・サイズ） |
| `01_非機能要求グレード/01_非機能要求グレード.md` | データ保管期間・バックアップ要件・拡張性要件 |

マネージドサービスを利用する場合は、ベンダーが管理するストレージ範囲を先に確認し、「お客様が設定できる項目」と「ベンダー管理の項目」を区別して記載する。

### Step 3: ユーザーへのヒアリング

以下の観点でシステムのストレージ要件を確認する：

**データ配置方針**
- どのデータをどのストレージに配置するか（アプリケーションファイル・ログ・一時ファイル・バックアップ等）
- お客様がアプリケーション用に追加の AWS S3 バケットを利用するか
- ユーザーアップロードファイル（本人確認書類等）の保存先とアクセス方式

**EBS ボリューム設計**
- 各ボリュームの用途と想定データ量
- ルートボリューム / アプリケーションボリューム の使い分け方針
- KVS・セッション管理用ストレージの要否とデータ量見積もり

**ストレージ容量計画**
- 初期データ量・月次増加量の見積もり
- 将来のスケールアップ方針（容量増加オプションと制約）
- 容量増設の判断基準（例: 使用率 80% 超過時に増設申込）

**バックアップ設計**
- バックアップスケジュール（日次/週次/月次の組み合わせ）
- バックアップ世代管理（保管世代数の要件とプラットフォーム制約）
- リストア手順・リストア時の影響範囲
- 保管期間の要件

**アクセス制御・暗号化**
- ストレージアクセスの権限分離方針
- 保存データの暗号化（基盤側で実施済みか、追加対応が必要か）

### Step 4: 各セクションへの記述

ヒアリング結果をもとに、以下のフォーマットで各ストレージを記述する。

```markdown
### ＜ストレージ名＞

**用途**: ＜このストレージの用途＞
**サイズ**: ＜容量＞
**種別**: ＜SSD/HDD/オブジェクトストレージ等＞
**配置場所**: ＜どのサーバ・AWSサービスにアタッチ/関連するか＞
**アクセス方式**: ＜SFTP/ファイル操作機能/アプリケーション経由 等＞
**暗号化**: ＜暗号化方式・責任範囲＞
**バックアップ**: ＜バックアップ方式・スケジュール・世代数＞
**設定可否**: ＜お客様が設定できる項目と制約＞
```

- マネージドサービスを利用する場合は「お客様が設定できる項目」と「ベンダー管理の項目」を区別して記載する
- 容量の根拠を明記する
- 未確定事項は `> **TODO:**` で明示する

### Step 5: レビューチェック

- [ ] データ配置方針にすべてのデータ種別（アプリ・ログ・バックアップ・一時ファイル等）が記述されているか
- [ ] EBS ボリューム設計がクラウドサービス設計書（`03_クラウドサービス/`）・サーバ設計書（`04_サーバ/`）のボリューム定義と一致しているか
- [ ] バックアップ設計の保管期間が非機能要求グレード（`01_非機能要求グレード/`）の要件と整合しているか
- [ ] バックアップ世代管理の保管世代数とプラットフォーム制約が検討されているか
- [ ] 容量増設計画の閾値・増設オプションが記述されているか
- [ ] お客様独自の S3 バケット（アプリデータ・ユーザーアップロード等）の要否が検討されているか
- [ ] 各ストレージの暗号化方式・責任範囲が記述されているか

## テンプレートの構成

テンプレート（`templates/基盤概要設計_ストレージ編_template.md`）は以下のセクションで構成される：

| セクション | 内容 |
|---|---|
| データ配置方針 | データ種別ごとのストレージ割り当て方針 |
| EBS 設計 | EC2 にアタッチされる各ボリュームの定義 |
| RDS ストレージ設計 | RDS DBインスタンスのストレージ定義 |
| S3 設計 | バックアップ用 S3・アプリデータ用バケットの定義 |
| アプリケーションストレージ設計 | アプリケーションファイル配置設計 |
| バックアップ設計 | スケジュール・世代管理・リストア手順 |
| 容量増設計画 | 増設判断基準・増設オプション |
