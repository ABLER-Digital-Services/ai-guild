## EBS 設計

本システムで使用する EC2 インスタンスにアタッチされる EBS ボリュームの定義。

### APサーバ — ルートボリューム（本番）

| 項目 | 内容 |
|---|---|
| 用途 | OS・システム領域 |
| サイズ | ＜容量＞ GiB |
| 種別 | SSD（EBS） |
| 配置 | APサーバ（本番・EC2） |
| 暗号化 | 基盤側で実施（ベンダー管理） |
| 設定可否 | **設定不可**（ベンダー管理） |
| 拡張 | 不可 |

### APサーバ — アプリケーションボリューム（本番）

| 項目 | 内容 |
|---|---|
| 用途 | アプリケーションストレージ・アプリケーションモジュール配置領域 |
| サイズ | ＜容量＞ GiB |
| 種別 | SSD（EBS） |
| 配置 | APサーバ（本番・EC2） |
| アクセス方式 | 管理コンソール・デプロイ機能（デプロイ）、SFTP（ログ取得） |
| 暗号化 | 基盤側で実施（ベンダー管理） |
| 設定可否 | **一部設定可**（モジュールデプロイは管理コンソール経由） |
| 拡張 | 不可（容量不足時は Storageサーバのストレージボリューム増設を検討） |

### Storageサーバ — ストレージボリューム（本番）

| 項目 | 内容 |
|---|---|

## バックアップ設計

バックアップ機能（スナップショット）を使用したバックアップ設計。
**バックアップの実施はお客様の責任**。

### バックアップ対象

| 対象 | バックアップ方式 | 備考 |
|---|---|---|
| APサーバ 全ボリューム（ルート・アプリケーション） | スナップショット（EC2） | バックアップ機能経由 |
| Storageサーバ 全ボリューム（ルート・ストレージ・セッション管理） | スナップショット（EC2） | 同上 |
| RDS 全ボリューム（DBボリューム） | スナップショット（RDS） | 同上 |

### バックアップスケジュール設計

バックアップ保持要件を実現するための設計：

| スケジュール名 | 取得周期 | 取得時刻 | 保持世代 | 実質保存期間 |
|---|---|---|---|---|
| 日次バックアップ | 毎日 | AM 01:00 | 3世代 | 直近3日分 |
| 週次バックアップ | 毎週日曜 | AM 02:00 | 3世代 | 直近3週分 |
| 月次バックアップ | 毎月1日 | AM 03:00 | 3世代 | 直近3か月分 |

> **注記**: 日次3世代のみでは長期保持要件を満たせない場合がある。複数スケジュールを組み合わせる運用設計を検討し、お客様と合意すること。サービス仕様書で世代数制限を確認すること。

### リストア手順・制約

| 項目 | 内容 |
|---|---|
| リストア操作 | 管理コンソール「リストア」から実行 |
| リストア範囲 | 全データがバックアップ時点に復元される（個別ファイル・テーブルの部分復元は不可） |
| リストア後の状態 | リストア前の状態への再リストアは不可 |
| ベンダー保守作業前のバックアップ | ベンダー保守作業前のバックアップは選択不可な場合がある |
| 実施通知 | バックアップ完了はメール通知（設定による） |
| プラン変更後のリストア | プラン変更後はプラン変更前のバックアップデータからのリストア不可な場合がある |
