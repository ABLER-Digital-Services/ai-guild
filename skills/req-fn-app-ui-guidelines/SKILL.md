# UI規約スキル

システム全体に適用するUI標準（レイアウト・コンポーネント・アクセシビリティ・入力規約など）を定義し、設計・開発の一貫性を担保するドキュメントを作成する。

## When to Use This Skill

- 「UI規約を作って」「UI仕様を整理して」と言われたとき
- 「画面の規約を決めて」「デザインルールをまとめて」と言われたとき
- 「コンポーネント規約を定義して」「アクセシビリティ要件を整理して」と言われたとき
- 既存のUI規約をレビュー・更新するとき
- 画面定義や画面遷移図を作る前の前提ルールを固めるとき

## 成果物の仕様

以下の格納先・ファイル名・ドキュメント単位は説明用の例です。実際の配置ルールは対象リポジトリ側の instructions、CONTRIBUTING、README などに従ってください。


- **格納先**: `docs/01_要件定義/01_機能/11_UI規約/`
- **ファイル名**: `01_UI規約.md`
- プロジェクトで原則1ドキュメント（画面定義や画面遷移の規範として機能する）

## 作成ワークフロー

### Step 1: 前提情報のヒアリング

ユーザーに以下を確認する：

1. **サービス種別**: 業務システム（BtoB）か、一般ユーザー向け（BtoC）か、社内管理画面か
2. **デバイス対応**: PC専用か、スマートフォン・タブレット対応か（モバイルファースト or デスクトップファースト）
3. **UIフレームワーク**: デザインシステム・コンポーネントライブラリの採用予定（Bootstrap / MUI / Ant Design / Tailwind / 独自など）
4. **アクセシビリティ要求**: 公共システムか否か（JIS X 8341-3 / WCAG 2.1 AA 準拠が必要か）
5. **サポートブラウザ・OS**: ユーザー環境（社内PCと社外デバイスで異なる場合あり）
6. **テーマ**: ダークモード対応の要否

### Step 2: ドキュメント骨格の選択

前提情報をもとに、以下のセクションを採用するか判断する：

| セクション | BtoB業務システム | BtoC / 公共 |
|---|---|---|
| デザイントークン | 推奨 | 必須 |
| ダークモード | 任意 | 任意 |
| アクセシビリティ規約 | 推奨 | 必須（WCAG AA） |
| レスポンシブ規約 | 任意（PC中心の場合） | 必須 |
| 帳票・印刷 | 必要に応じて | 任意 |

### Step 3: ドキュメント生成

`templates/ui-guidelines-template.md` を元にドキュメントを生成する。

以下のルールを守ること：

- **色・サイズ・スペーシングは具体的な値で定義する**（「大きめのボタン」などの曖昧な表現は避ける）
- **コンポーネントごとにバリアント（種類）とステート（状態）を明示する**
- **バリデーションとエラー表示のパターンはデータ型ごとに定義する**
- **WCAG / JIS X 8341-3 の要求レベル（A / AA / AAA）を明記する**
- アクターや機能一覧が既に定義されている場合は、画面に関連するアクターの記述と照合する

### Step 4: レビューチェック

- [ ] サポートデバイス・ブラウザが明確に定義されているか
- [ ] デザイントークン（色・フォント・スペーシング・ブレークポイント）が数値で定義されているか
- [ ] すべてのコンポーネントにバリアントとステート（通常・ホバー・押下・無効・フォーカス）が定義されているか
- [ ] フォームのバリデーション規約（タイミング・エラー表示）が定義されているか
- [ ] アクセシビリティ要求レベルが明示され、対応方針が記載されているか
- [ ] レスポンシブ対応（ブレークポイントごとのレイアウト変化）が定義されているか
- [ ] メッセージ種別（情報・成功・警告・エラー）と表示パターンが定義されているか
- [ ] ローディング・空状態・エラー状態の画面パターンが定義されているか

## ドキュメント作成上の重要ポイント

### デザイントークン

色・サイズ・スペーシングはCSS変数やデザインツールのトークンで管理する。

```css
/* 例 */
--color-primary: #1D4ED8;
--color-danger:  #DC2626;
--spacing-md:    16px;
--radius-md:     8px;
```

デザイナー・エンジニア間の乖離を防ぎ、テーマの一括変更を可能にする。

### コンポーネントステート

各コンポーネントに以下のステートを定義する：

| ステート | 説明 |
|---|---|
| Default | 通常状態 |
| Hover | マウスオーバー時 |
| Active / Pressed | クリック・タップ中 |
| Focus | キーボードフォーカス時（アクセシビリティ必須） |
| Disabled | 操作不可状態 |
| Loading | 非同期処理中 |
| Error | 入力エラー・バリデーション失敗 |

### ページ状態パターン

SPAや動的画面では、コンテンツ表示以外の状態定義が必須：

| 状態 | 説明 | 対応UI |
|---|---|---|
| Loading | データ取得中 | スケルトンスクリーン / スピナー |
| Empty | データが0件 | 空状態イラスト＋誘導テキスト |
| Error | API失敗・例外 | エラーメッセージ＋再試行ボタン |
| Partial Error | 一部データ取得失敗 | インラインエラー表示 |

### アクセシビリティ（WCAG 2.1 AA 準拠の主要ポイント）

| 要件 | 基準 |
|---|---|
| カラーコントラスト（通常テキスト） | 4.5:1 以上 |
| カラーコントラスト（大きなテキスト 18px以上） | 3:1 以上 |
| キーボード操作 | すべての操作がキーボードのみで実行可能 |
| フォーカスインジケータ | 視覚的に明確なフォーカスリングを表示 |
| フォーム要素 | `<label>` と入力要素の紐づけ必須 |
| 代替テキスト | 情報を持つ画像に `alt` 属性必須 |
| エラー識別 | 色だけでなくテキストでもエラーを識別可能にする |
