# UI規約

## 1. はじめに

### 1.1 本書の目的

本書は〔システム名〕のUI（ユーザーインターフェース）設計・実装に関する標準規約を定めるものである。
本規約に従うことで、以下を実現する。

- アクターおよびシステム横断での一貫したユーザー体験
- 設計・開発・レビューにおける判断基準の統一
- アクセシビリティ要求への対応

### 1.2 対象読者

| 読者 | 目的 |
|---|---|
| UIデザイナー | 画面設計・コンポーネント設計時の基準 |
| フロントエンドエンジニア | 実装時のルール確認 |
| バックエンドエンジニア | 入力値・エラーレスポンス設計の参照 |
| レビュアー | 成果物レビュー時のチェック基準 |

### 1.3 留意事項

- 本規約は〔プロジェクト名〕固有の規約である。一般的なWebアクセシビリティ標準（WCAG 2.1）とJIS X 8341-3を参照基準とする
- 個別の画面仕様は「画面定義書」に記載する。規約と個別仕様が矛盾する場合は、設計担当者間で協議のうえ規約を改訂する
- コードレベルの実装詳細（クラス名・プロパティ値）は別途フロントエンド設計書に記載する

## 3. デザイン原則

### 3.1 基本方針

1. **一貫性**: 同じ意味・操作には同じUIパターンを使う
2. **明瞭性**: 操作の結果・システム状態をユーザーに明確に伝える
3. **フィードバック**: 操作に対して即座に視覚的フィードバックを返す
4. **エラー防止**: 不可逆な操作には確認ダイアログを挟む
5. **アクセシビリティ**: キーボードのみ・スクリーンリーダーでも操作可能にする

### 3.2 レスポンシブデザイン方針

- **モバイルファースト** を基本とし、ブレークポイントごとにレイアウトを拡張する
- コンテンツの優先順位: モバイルで最も重要なコンテンツを画面上部に配置する
- 水平スクロールは禁止する（テーブル内部は除く）

## 5. 画面レイアウト

### 5.1 レイアウトグリッド

| ブレークポイント | カラム数 | ガター | マージン（左右） |
|---|---|---|---|
| 〜 md | 4列 | 16px | 16px |
| md 〜 lg | 8列 | 24px | 24px |
| lg 〜 | 12列 | 24px | 32px |

### 5.2 主要レイアウトパターン

| パターン名 | 説明 | 適用画面例 |
|---|---|---|
| 全幅レイアウト | コンテンツが画面幅いっぱいに広がる | ダッシュボード・一覧画面 |
| センタリング固定幅 | 最大幅（例: 1200px）でセンタリング | フォーム・詳細画面 |
| サイドバー付き | 左サイドナビ（lg以上で展開） | 管理システム全般 |
| スタック（モバイル） | 垂直積み上げ | モバイル全般 |

### 5.3 ヘッダ

| 項目 | 仕様 |
|---|---|
| 高さ | 60px（デスクトップ） / 56px（モバイル） |
| 固定方法 | 画面最上部に固定（スクロール追従） |
| 含める要素 | ロゴ・グローバルナビ・ユーザーメニュー・通知アイコン |
| モバイル | ハンバーガーメニューでナビをドロワー展開 |

### 5.4 サイドナビゲーション

| 項目 | 仕様 |
|---|---|
| 幅 | 展開 240px / 折りたたみ 64px |
| 表示条件 | lg（1024px）以上で常時表示 |
| モバイル | ドロワー形式でオーバーレイ表示 |
| アクティブ状態 | 背景色 `--color-primary-light`・テキスト `--color-primary` |

### 5.5 コンテンツエリア

- ページタイトル・パンくずリストをコンテンツ最上部に配置する
- ページタイトルの下に操作ボタン（主要アクション）エリアを置く
- メッセージエリアはタイトルとコンテンツの間に表示する

### 5.6 フッタ

| 項目 | 仕様 |
|---|---|
| 表示 | 固定フッタは使用しない（コンテンツ下部に自然配置） |
| 含める要素 | コピーライト・利用規約リンク・プライバシーポリシーリンク |

## 6. コンポーネント規約

### 6.1 ボタン

#### バリアント

| バリアント | 用途 | 見た目 |
|---|---|---|
| Primary | 主要アクション（1画面に1つ） | 塗りつぶし・`--color-primary` |
| Secondary | 副次アクション | 枠線のみ |
| Danger | 削除・取消などの危険操作 | 塗りつぶし・`--color-danger` |
| Ghost | テキストリンク的な操作 | 背景なし・テキストのみ |
| Icon | アイコン単体ボタン | 正方形・アイコンのみ |

#### サイズ

| サイズ | 高さ | フォント | 用途 |
|---|---|---|---|
| sm | 32px | 14px | テーブル内・補助操作 |
| md（標準） | 40px | 16px | 一般フォーム操作 |
| lg | 48px | 18px | CTA・目立たせたい操作 |

#### ステート

| ステート | 表現 |
|---|---|
| Default | 通常状態 |
| Hover | 明度10%下げ |
| Active | 明度20%下げ |
| Focus | `outline: 2px solid --color-primary` |
| Disabled | opacity 0.4・`cursor: not-allowed` |
| Loading | ボタンテキストをスピナーに置き換え・`disabled` 属性付与 |

#### ルール

- 1画面に Primary ボタンは原則1つのみ
- 「削除」「取消」など不可逆操作は Danger バリアントを使い、確認ダイアログを必須とする
- ボタングループ内では右端に Primary を配置する
- タッチターゲットは最小 44×44px を確保する（WCAG 2.5.8）

### 6.2 フォーム要素

#### テキスト入力（Input）

| 項目 | 仕様 |
|---|---|
| 高さ | 40px（標準） |
| 枠線 | `1px solid --color-border` |
| フォーカス時 | `2px solid --color-primary`・shadow なし |
| エラー時 | `1px solid --color-danger`・エラーメッセージを下部に表示 |
| プレースホルダー | 入力例を示す（ラベルの代替には使わない） |

#### セレクト（Select）

- ネイティブ `<select>` またはカスタムコンポーネントを使用する
- 選択肢が6件を超える場合は検索機能を付与することを推奨する

#### チェックボックス・ラジオボタン

- タッチターゲットは最小 44×44px を確保する
- ラベルをクリックしても選択できるようにする（`<label>` と紐づけ必須）
- グループには `<fieldset>` と `<legend>` を使用する

#### テキストエリア（Textarea）

- 文字数制限がある場合は残り文字数カウンターを表示する
- 最小高さ: 4行分（約96px）

#### ファイルアップロード

- ドラッグ＆ドロップ領域と「ファイルを選択」ボタンを並置する
- 許容ファイル形式・最大ファイルサイズを領域内またはラベル下に明示する
- アップロード中はプログレスバーを表示する

### 6.3 テーブル

| 項目 | 仕様 |
|---|---|
| ヘッダ | 背景 `--color-bg-page`・テキスト`--color-text-secondary`・`font-weight: 600` |
| 行高さ | データ行 52px（標準）/ 密集表示 40px |
| ストライプ | 偶数行に薄背景（`--color-bg-page`）を適用する（任意） |
| ホバー | 行ホバーで背景色変化 |
| 選択行 | `--color-primary-light` 背景 |
| ソート | ソート可能列は列ヘッダにアイコンを表示し、クリックで昇降順切替 |
| レスポンシブ | md未満では横スクロール可能なラッパーで包む |
| 空状態 | データ0件時は「データがありません」メッセージ＋誘導アクションを表示する |

### 6.4 カード

| 項目 | 仕様 |
|---|---|
| 角丸 | `--radius-lg` |
| 影 | `--shadow-sm`（通常）・`--shadow-md`（ホバー・強調） |
| 背景 | `--color-bg-surface` |
| 内部余白 | `--spacing-lg`（24px） |
| クリッカブルカード | カード全体がリンクの場合、`cursor: pointer`・ホバーで `--shadow-md` に変化 |

### 6.5 モーダル・ダイアログ

| 種別 | 用途 | 幅 |
|---|---|---|
| 確認ダイアログ | 削除・送信など不可逆操作の確認 | 400px |
| 入力モーダル | フォーム入力 | 600px |
| 詳細モーダル | コンテンツ表示 | 800px |
| フルスクリーン | 複雑な操作・ファイル選択 | 画面幅 |

#### ルール

- オーバーレイ背景は `rgba(0,0,0,0.5)` を使用する
- 表示時は背景のスクロールをロックする
- ESCキーで閉じられるようにする
- フォーカストラップを実装する（WAI-ARIA Modal Authoring Practices 準拠）
- `role="dialog"` と `aria-modal="true"` を指定する
- モーダルタイトルを `aria-labelledby` で関連付ける

### 6.6 ナビゲーション

#### パンくずリスト

- 3階層以上の画面に必ず表示する
- 現在ページはリンクにしない（テキストのみ）
- 区切り文字: `>` または `/`

#### ページネーション

| 項目 | 仕様 |
|---|---|
| 表示形式 | 「前へ」「次へ」ボタン＋ページ番号 |
| 1ページの件数 | 標準20件・ユーザーが25/50/100件に変更可能 |
| 総件数表示 | 「全〇〇件中 〇〇〜〇〇件を表示」 |

#### タブ

- 選択中タブは `aria-selected="true"` を設定する
- キーボード操作: 左右矢印キーでタブ切替、Enter/Spaceで選択

#### ドロップダウンメニュー

- トリガーボタンに `aria-expanded`・`aria-haspopup` を設定する
- ESCキー・フォーカス外れで閉じる
- 開閉アニメーション: 200ms フェードイン

### 6.7 通知・フィードバック

#### トースト通知

| 種別 | 用途 | 自動消去 |
|---|---|---|
| Success | 操作の成功（保存完了など） | 3秒後 |
| Info | お知らせ・ガイダンス | 5秒後 |
| Warning | 警告（操作は成功したが注意あり） | 手動 |
| Error | 操作失敗・エラー | 手動 |

- 表示位置: 画面右上（デスクトップ）/ 画面下部（モバイル）
- 最大同時表示: 3件（超えたら古い順に削除）
- `role="alert"` または `aria-live` 領域に配置する

#### インラインメッセージ（バナー）

- フォーム全体のエラーや重要な操作結果を画面上部に表示する
- アイコン＋テキストで色に依存しない識別を行う

#### バッジ

- 未読件数・件数カウントを示す数値バッジには最大表示数（例: `99+`）を設定する

### 6.8 ローディング状態

| パターン | 用途 |
|---|---|
| スケルトンスクリーン | ページ初回ロード・リスト・カード取得中 |
| スピナー（全画面） | ユーザー操作への応答待ち（フォーム送信中など） |
| スピナー（インライン） | ボタン内・コンポーネント内の一部更新 |
| プログレスバー | ファイルアップロード・段階的処理 |

- 500ms 以上かかる処理にはローディングインジケーターを表示する
- 全画面スピナー表示中はページ操作を無効化する

## 7. 画面遷移とナビゲーション

### 7.1 画面の種類

| 種別 | 説明 | 用途 |
|---|---|---|
| フルページ | URLが変わる通常画面 | 一覧・詳細・設定など |
| モーダル | 前画面の上に重なるダイアログ | 確認・簡易入力 |
| ドロワー | 画面端からスライドして出るパネル | フィルター・詳細サイドパネル |
| トースト | 一時的な通知 | 操作フィードバック |

### 7.2 遷移パターン

| パターン | 説明 |
|---|---|
| 登録後リダイレクト | 登録成功後は詳細画面または一覧画面にリダイレクトする |
| 編集後リダイレクト | 更新成功後は元の詳細画面に戻す |
| 削除後リダイレクト | 削除成功後は一覧画面にリダイレクトする |
| エラー時留まり | 入力エラー・API失敗時は同画面に留まりエラーを表示する |

### 7.3 ページ状態パターン

| 状態 | UIパターン |
|---|---|
| Loading（初期表示中） | スケルトンスクリーン |
| Empty（データ0件） | イラストまたはアイコン＋「データがありません」＋誘導アクションボタン |
| Error（取得失敗） | エラーメッセージ＋「再読み込み」ボタン |
| Partial Error（一部失敗） | 取得できているデータを表示し、エラー部分にインラインメッセージを表示 |

### 7.4 戻る・キャンセルの振る舞い

- **フォームに未保存の変更がある場合**: 離脱確認ダイアログを表示する
- **ブラウザの戻るボタン**: 原則として前の画面に戻る（SPAのhistory管理を正しく実装する）

## 8. 入力・バリデーション規約

### 8.1 バリデーションタイミング

| タイミング | 用途 |
|---|---|
| `onBlur`（フォーカス離脱時） | 入力完了を検知してリアルタイムバリデーション |
| `onSubmit`（送信時） | 全フィールドの最終チェック |
| `onChange`（文字入力中） | 文字数カウンター・禁止文字制御のみ |

### 8.2 エラー表示パターン

- エラーメッセージは対象の入力欄の直下に表示する
- 色（赤）だけでなくアイコンとテキストを組み合わせて識別する
- 入力欄の枠線を `--color-danger` で赤くする
- エラー数が複数の場合、画面上部にエラー項目リストを表示する（アンカーリンク付き）

### 8.3 データ型別入力規約

> 詳細は「別紙1 データ型別入力・表示フォーマット一覧」参照

| データ型 | 入力形式 | バリデーションルール |
|---|---|---|
| 日付 | `YYYY/MM/DD`（ピッカー推奨） | 存在する日付・範囲チェック |
| 日時 | `YYYY/MM/DD HH:mm` | 存在する日時・範囲チェック |
| 電話番号 | ハイフンあり（例: `03-1234-5678`） | 数字・ハイフンのみ |
| メールアドレス | RFC 5321 準拠 | メール形式チェック |
| 郵便番号 | `NNN-NNNN` | 7桁数字＋ハイフン |
| 金額 | 数字のみ（カンマ区切り表示） | 正の整数・最大桁数チェック |
| パスワード | マスク入力 | 8文字以上・英数記号混在 |

### 8.4 必須・任意の表示

- **必須項目**: ラベル末尾に `*`（赤）を付与する
- **任意項目**: ラベル末尾に「（任意）」を付与する（任意が少数の場合に使用）

## 9. メッセージ・通知規約

### 9.1 メッセージ種別

| 種別 | 意味 | アイコン | 色 |
|---|---|---|---|
| Success | 操作完了・保存成功 | ✓ チェックマーク | `--color-success` |
| Info | お知らせ・ヘルプ | i インフォ | `--color-info` |
| Warning | 注意・警告（操作は続行可能） | ! トライアングル | `--color-warning` |
| Error | エラー・操作失敗（操作要） | ✕ バツ | `--color-danger` |

### 9.2 確認ダイアログ

不可逆な操作（削除・確定・送信）の前に必ず確認ダイアログを表示する。

| 項目 | 内容 |
|---|---|
| タイトル | 操作名（例:「〇〇を削除しますか？」） |
| 本文 | 操作の結果と影響の簡潔な説明 |
| 肯定ボタン | 表現を操作名に合わせる（「削除する」「送信する」） |
| 否定ボタン | 「キャンセル」（Secondary または Ghost） |
| ボタン配置 | 肯定ボタンを右、否定ボタンを左 |

### 9.3 API エラーメッセージ

| エラー種別 | 表示メッセージ例 |
|---|---|
| ネットワークエラー | 「通信エラーが発生しました。時間をおいて再度お試しください。」 |
| 認証エラー（401） | 「セッションが切れました。再ログインしてください。」 |
| 権限エラー（403） | 「この操作を行う権限がありません。」 |
| 未検出（404） | 「お探しのデータが見つかりませんでした。」 |
| サーバーエラー（5xx） | 「システムエラーが発生しました。しばらく経ってから再度お試しください。」 |

- エラーコードや技術的な詳細はユーザーに見せない
- サポート問い合わせが必要なエラーにはエラーIDを表示する

## 10. アクセシビリティ規約

### 10.1 準拠基準

- WCAG 2.1 適合レベル **AA**

### 10.2 キーボード操作

- すべてのインタラクティブ要素（ボタン・リンク・フォーム・タブ・モーダル）をキーボードのみで操作できること
- `Tab` キーでフォーカス移動できること
- `Enter` / `Space` で操作実行できること
- `Esc` でモーダル・ドロップダウンを閉じられること
- 論理的なフォーカス順序（DOM順）を維持すること

### 10.3 フォーカスインジケータ

- フォーカスリングは `outline: 2px solid --color-primary` を使用する
- `:focus-visible` を使用してキーボード操作時のみ表示する
- フォーカスリングを `outline: none` で非表示にしてはならない

### 10.4 カラーコントラスト

| 種別 | 最低コントラスト比 |
|---|---|
| 通常テキスト（18px未満） | 4.5:1 |
| 大きなテキスト（18px以上 / Bold 14px以上） | 3:1 |
| UIコンポーネント・グラフィック要素 | 3:1 |

### 10.5 スクリーンリーダー対応

- すべての画像に適切な `alt` 属性を設定する（装飾目的の場合は `alt=""`）
- フォーム要素には `<label>` を紐づける（`for` 属性または `aria-label`）
- アイコン単体ボタンには `aria-label` を設定する
- ダイナミックコンテンツの更新は `aria-live` 領域で通知する
- ページタイトルは遷移のたびに更新する（`<title>` タグ）

### 10.6 動き・アニメーション

- `prefers-reduced-motion` を尊重し、Reduced Motion 設定時はアニメーションを最小化する

## 11. 利用技術規定

### 11.1 HTML

- セマンティックなHTMLタグを使用する（`<header>`, `<nav>`, `<main>`, `<section>`, `<article>` など）
- ページ構造のランドマーク（`<main>` は1つのみ）を適切に使用する
- 文字コード: UTF-8

### 11.2 CSS

- CSS変数（カスタムプロパティ）で4章のデザイントークンを管理する
- CSSフレームワーク: （例）Tailwind CSS / MUI / 独自設計
- グローバルスタイルのリセットには（例）`normalize.css` または `@tailwind base` を使用する
- コンポーネント単位でスタイルをスコープする（CSS Modules / styled-components / Tailwind など）

### 11.3 JavaScript / フレームワーク

| 項目 | 採用技術 |
|---|---|
| フロントエンドフレームワーク | （例）React 18 / Vue 3 / Angular |
| 状態管理 | （例）Redux Toolkit / Pinia / Zustand |
| ルーティング | （例）React Router v6 / Vue Router |
| フォーム管理 | （例）React Hook Form / Vee-Validate |

### 11.4 アイコン

- アイコンセット: （例）Heroicons / Material Icons / Phosphor Icons
- アイコンのみのボタンには必ず `aria-label` を設定する
- 意味を持つアイコンには `aria-hidden="false"` と代替テキストを設定する
- 装飾目的のアイコンには `aria-hidden="true"` を設定する

### 11.5 画像・メディア

- フォーマット: WebP を優先（フォールバック: PNG / JPEG）
- `<img>` には `width` / `height` 属性を指定してCLSを防止する
- 遅延読み込み: スクロールで表示される画像には `loading="lazy"` を設定する
- 動画には字幕（`<track>` 要素）を提供する
