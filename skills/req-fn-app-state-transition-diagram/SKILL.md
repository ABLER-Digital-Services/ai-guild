# 状態遷移図スキル

ステータスを持つエンティティの状態一覧と遷移条件を図で定義する。
エンティティ（注文・申請・会員など）ごとに1ファイル作成する。

## When to Use This Skill

- 「状態遷移図を作って」「ステータスの遷移を整理して」と言われたとき
- 特定エンティティのステータス設計を明確にしたいとき
- 既存の状態遷移図をレビュー・更新するとき

## 作成ワークフロー

### Step 1: 形式の選択（必ずユーザーに確認する）

**最初にユーザーに以下を確認すること：**

> Mermaid（`stateDiagram-v2`）と draw.io のどちらで作成しますか？
> - **Mermaid**: テキストで管理できGitでの差分確認が容易。ただし複雑な図では表示が崩れる場合があります。
> - **draw.io**: 複雑な遷移でも見やすく作れます。図の編集はdraw.ioアプリが必要です。

### Step 2: 対象エンティティの確認

1. **エンティティ名**: 何のステータスを定義するか（例: 注文、申請、会員）
2. **状態一覧**: 取りうるすべての状態（ステータス値と表示名）
3. **遷移条件**: どの状態からどの状態へ、どんなイベントで遷移するか
4. **初期状態**: エンティティ生成時の初期ステータス
5. **終了状態**: フローが完結する終端ステータス（複数可）

### Step 3: ドキュメント生成

選択された形式のテンプレートを使用してドキュメントを生成する。

- **Mermaid形式**: `templates/state-transition-mermaid-template.md`
- **draw.io形式**: `templates/state-transition-drawio-template.md` + `.drawio`

共通ルール：
- 状態名はテーブル定義書のステータス値と一致させる
- 遷移のラベルには「トリガー（イベント）」を記載する
- 到達不可能な状態・遷移が存在しないか確認する

### Step 4: レビューチェック

- [ ] すべての状態が網羅されているか
- [ ] 初期状態（`[*]`）と終了状態（`[*]`）が定義されているか
- [ ] 状態名がテーブル定義書・画面定義のステータス表記と一致しているか
- [ ] 遷移ラベル（イベント名）が記載されているか
- [ ] 到達できない孤立した状態がないか

## 後続成果物との連携

- **テーブル定義** (`13_テーブル定義`) — ステータスカラムの値と状態名を一致させる
- **画面定義** (`10_画面定義`) — 各状態で表示・操作可能なボタンと遷移条件を画面定義に記載
- **処理一覧** (`05_処理一覧`) — 状態遷移を伴うボタン操作は処理一覧に記載
