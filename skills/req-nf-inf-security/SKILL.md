# セキュリティ要件定義書スキル

システムのセキュリティ要件を体系的に定義するドキュメントを作成・更新する。
非機能要求グレードのセキュリティ項目を詳細化した成果物として位置づけられる。

## When to Use This Skill

- 「セキュリティ要件定義書を作って」と言われたとき
- 「セキュリティ要件を詳細化して」「認証要件を定義して」「暗号化要件を整理して」と言われたとき
- 既存のセキュリティ要件定義書をレビュー・更新するとき

## 成果物の仕様

以下のパスやファイル名は説明用の例です。実際の配置ルールは対象リポジトリ側の instructions、CONTRIBUTING、README などに従ってください。


## テンプレートの構成

テンプレート（`templates/セキュリティ要件定義書_template.md`）は以下の9カテゴリで構成される：

| # | カテゴリ | 主なサブ項目 |
|---|---|---|
| 1 | アイデンティティ・アクセス管理要件 | アカウント管理・認証・認可・アクセス制御・職務分掌 |
| 2 | データ保護要件 | 通信暗号化・データ暗号化 |
| 3 | ネットワークセキュリティ要件 | 境界防御・ネットワーク分離・内部ネットワーク制御 |
| 4 | ロギング・監視要件 | 監査ログ取得・セキュリティ監視・インシデント対応 |
| 5 | 脆弱性管理要件 | 脆弱性検出・パッチ管理 |
| 6 | アセット管理要件 | 資産可視化・資産ライフサイクル管理 |
| 7 | インフラセキュリティ要件 | マルウェア対策・コンテナセキュリティ |
| 8 | APIセキュリティ要件 | API認証・認可 |
| 9 | サプライチェーンセキュリティ要件 | 委託先管理 |

この構成は「誰が→何を→どこで→いつ→予防→把握→サーバ→アプリ→外部」というストーリーで設計されており、セキュリティ対策を段階的に定義できる。

## 作成ワークフロー

### Step 1: テンプレートをコピーして成果物を作成

例として、`templates/セキュリティ要件定義書_template.md` を `docs/01_要件定義/02_非機能/08_セキュリティ/01_セキュリティ要件定義書.md` にコピーして作業を開始する。

`## 0. はじめに` 内の `＊＊＊システム` をプロジェクト名に置き換える。

### Step 2: 非機能要求グレードとの関係確認

非機能要求グレード相当の成果物が存在する場合は参照し、セキュリティカテゴリの選択内容と整合性を取る。

### Step 3: ユーザーへのヒアリング

カテゴリごとに以下の観点でシステムの特性を確認する：

**1. アイデンティティ・アクセス管理**
- 認証方式（ID/PW、MFA、SSO、証明書認証など）
- 特権アカウントの管理方針
- 権限モデル（RBAC/ABAC など）

**2. データ保護**
- 取り扱う機密データの種別（個人情報、決済情報など）
- 通信・保管時の暗号化要件（TLSバージョン、鍵長など）

**3. ネットワークセキュリティ**
- クラウド/オンプレミスの構成
- ファイアウォール・WAF・IDS/IPS の要否

**4. ロギング・監視**
- ログの取得対象・保管期間
- SIEM等のセキュリティ監視基盤の有無
- インシデント発生時の対応フロー

**5. 脆弱性管理**
- ペネトレーションテスト・脆弱性診断の実施予定
- パッチ適用の方針・タイムライン

**6. アセット管理**
- システム構成要素の棚卸し方針

**7. インフラセキュリティ**
- コンテナ（Docker/Kubernetes）の利用有無
- マルウェア対策ツールの導入方針

**8. APIセキュリティ**
- 公開APIの有無・認証方式（APIキー、OAuth2.0など）

**9. サプライチェーン**
- 外部委託先・SaaS利用の有無
- 委託先へのセキュリティ要件の課し方

### Step 4: 各セクションへの要件記述

ヒアリング結果を元に各 `---` で区切られたセクションに要件を記述する。

記述の基本スタイル：
- 要件は箇条書きで列挙する
- 「〜すること」「〜を禁止する」「〜を必須とする」など義務・禁止の表現を用いる
- 根拠となる法令・ガイドライン（個人情報保護法、PCI DSS、NIST等）があれば明記する

記述例：

```markdown
### 1.2. 認証要件

- 管理者アカウントは多要素認証（MFA）を必須とする
- パスワードは最低12文字以上とし、英大文字・小文字・数字・記号を含むこと
- ログイン試行を5回連続で失敗した場合、アカウントを30分間ロックすること
- セッションタイムアウトは無操作30分とする
```

### Step 5: レビューチェック

- [ ] 全9カテゴリにいずれかの要件が記述されているか（未着手の項目は「本システムでは対象外」と明示）
- [ ] 非機能要求グレードのセキュリティ選択内容と矛盾していないか
- [ ] 遵守すべき法令・ガイドライン（PCI DSS、個人情報保護法等）に対応する要件が漏れていないか
- [ ] 要件が具体的か（「適切に管理する」「十分なセキュリティ」などの曖昧表現になっていないか）
