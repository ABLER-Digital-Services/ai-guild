# 機能一覧スキル

システムが持つ全機能を一覧化する。機能IDを採番し、後続の処理一覧・インタフェース一覧・画面定義の参照キーとして機能させる。

## When to Use This Skill

- 「機能一覧を作って」「機能を整理して」と言われたとき
- 画面設計・処理設計の前に機能のスコープを確定したいとき
- 既存の機能一覧をレビュー・更新するとき

## 機能の粒度ルール

| 区分 | 粒度の単位 | 例 |
|---|---|---|
| **オンライン機能** | 1画面 ＝ 1機能 | 注文一覧画面、注文登録画面、注文詳細画面 |
| **バッチ機能** | 1ジョブ ＝ 1機能 | 請求締め処理、売上集計バッチ、データ連携バッチ |

- 1つの画面に複数のタブや大きなモードの切り替えがある場合は、サブ画面ごとに分けることを検討する
- バッチは「定期実行の1スケジュール単位」を1ジョブとして数える
- APIエンドポイントは原則オンライン機能として1機能に対応させる

## 機能ID採番ルール

| 区分 | フォーマット | 例 |
|---|---|---|
| オンライン機能 | `F-O-NNN` | `F-O-001`、`F-O-002` |
| バッチ機能 | `F-B-NNN` | `F-B-001`、`F-B-002` |

- NNNは3桁ゼロ埋め
- 一度採番したIDは欠番になっても振り直さない

## 作成ワークフロー

### Step 1: 機能の洗い出し（ヒアリング）

ユーザーに以下を確認する：

1. **オンライン機能**: どんな画面があるか（一覧・登録・編集・詳細・設定など）
2. **バッチ機能**: どんな定期処理・自動処理があるか
3. **対象アクター**: アクター定義書を参照し、各機能を使うアクターを確認する
4. **グルーピング**: 機能を「大カテゴリ（サブシステム・業務領域）」で束ねるか確認する

### Step 2: ドキュメント生成

`templates/feature-list-template.md` を元にドキュメントを生成する。

以下のルールを守ること：
- オンライン機能とバッチ機能はセクションを分けて記載する
- アクター列には、アクター定義書で定義した正式名称を記載する（複数の場合は `／` で区切る）
- 概要は「何をするための画面／処理か」を主語なしの体言止めで記載する

### Step 3: レビューチェック

- [ ] すべての画面・ジョブが網羅されているか
- [ ] 機能IDの採番形式（`F-O-NNN` / `F-B-NNN`）が守られているか
- [ ] アクター名がアクター定義書と一致しているか
- [ ] 概要が体言止めで記載されているか
- [ ] 処理一覧・画面遷移図・画面定義と整合しているか

## 後続成果物との連携

- **処理一覧** (`05_処理一覧`) — 機能IDを `関連機能ID` 列で参照する
- **インタフェース一覧** (`06_インタフェース一覧`) — バッチ機能と外部IFを紐づける際に機能IDを使う
- **画面遷移図** (`09_画面遷移図`) — オンライン機能名と画面名を一致させる
- **画面定義** (`10_画面定義`) — 機能IDと画面定義ファイルを1対1で対応させる
