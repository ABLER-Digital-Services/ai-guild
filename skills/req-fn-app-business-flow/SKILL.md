# 業務フロースキル

複数のアクターにまたがる業務プロセスをスイムレーン形式の draw.io 図として作成する。
すべての業務を対象にするのではなく、フロー可視化が必要なケースに絞って作成する。

## When to Use This Skill

- 「業務フローを作って」「〇〇処理のフローを書いて」と言われたとき
- 複数アクターが関わる処理の流れを整理・可視化したいとき
- 判断分岐や例外処理が発生する業務プロセスを記述したいとき
- 既存の業務フロー図をレビュー・更新するとき

## 作成ワークフロー

### Step 1: 対象業務の確認

ユーザーに以下を確認する：

1. **対象業務名**: どの業務プロセスを描くか
2. **登場アクター**: 誰が（システム含む）関わるか → アクター定義書を参照
3. **開始・終了条件**: フローはどこから始まり、どこで終わるか
4. **主フロー**: 正常系の処理の流れ
5. **分岐・例外**: 条件分岐や例外処理はあるか

### Step 2: draw.io ファイルの生成

draw.io MCP (`mcp_drawio_open_drawio_xml`) を使い、スイムレーン形式のXMLを生成する。
`templates/business-flow-template.drawio` のXMLを元にアクター数・処理ステップ数を調整する。

**スイムレーンのルール:**
- 各アクターを1レーン（縦列）として左右に並べる
- レーン順: 利用者系アクター（左）→ システム（中）→ 外部システム（右）
- フローは上から下へ進む（縦長レイアウト）
- 処理ステップは角丸矩形、判断分岐はひし形、開始/終了は楕円
- レーン間の矢印には処理内容のラベルを付ける
- 正常系と例外系は線のスタイルで区別する（実線／破線）

### Step 3: Markdownラッパーの作成

`templates/business-flow-template.md` を元にMarkdownを作成する。

記載内容：
- 対象業務の概要・背景
- 登場アクター一覧（アクター定義書のIDとの対応）
- draw.io ファイルへの相対リンク
- フローの補足説明（判断条件・例外処理の詳細など）
- 関連ドキュメントへのリンク

### Step 4: レビューチェック

- [ ] アクター名がアクター定義書と一致しているか
- [ ] 開始・終了が明確に定義されているか
- [ ] 正常系・例外系が区別されているか
- [ ] 判断分岐の条件がラベルに記載されているか
- [ ] レーン間の矢印にラベルが付いているか
- [ ] draw.io ファイルとMarkdownファイルが同じ連番・名称で対になっているか
