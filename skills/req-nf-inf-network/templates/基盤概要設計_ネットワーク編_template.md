## 設計方針・前提条件

### 設計方針

| 方針 | 内容 |
|---|---|
| セキュリティゾーニング | Public / Private / Isolated の3層に分離する。インターネット向けリソースは Public のみ、DBは Isolated のみに配置する |
| 冗長化 | ＜マルチAZ構成とする / シングルAZ構成とする＞ |
| 環境分離 | ＜本番・開発を VPC レベルで分離する / サブネットレベルで分離する＞ |
| 命名規則 | `<システムID>-<環境>-<リソース種別>-<AZ>` の形式とする（例: `mysys-prod-public-1a`） |

### 管理責任の分担

<!-- ＜クラウドプラットフォーム＞ 環境の場合 -->
| 設計要素 | 管理責任 | お客様の操作余地 |
|---|---|---|
| VPC / サブネット / AZ 構成 | **＜ベンダー管理 / お客様管理＞** | 設定不可（仕様書の定義に従う） |
| ルートテーブル / IGW / NAT GW | **＜ベンダー管理 / お客様管理＞** | 設定不可 |
| セキュリティグループ（ベース） | **＜ベンダー管理 / お客様管理＞** | 追加ルールは申込で対応 |
| IPアドレス制限（管理サイト・SFTP） | **お客様管理** | 運用管理サイトで設定可 |
| VPCピアリング（外部AWS環境） | **お客様申請** | AMP への申込が必要 |
| WAF ルール（基本セット） | **＜ベンダー提供 / お客様管理＞** | 独自ルール追加は別途申込 |

## ネットワーク全体構成

### セキュリティゾーン設計

本システムのネットワークを以下のゾーンに分割する。

| ゾーン | 種別 | 配置リソース | インターネット接続 |
|---|---|---|---|
| Public ゾーン | Public サブネット | ALB・NAT Gateway・CloudFront | 直接接続可 |
| Application ゾーン | Private サブネット | EC2（APサーバ・Storageサーバ） | NAT GW 経由のみ（アウトバウンド） |
| Database ゾーン | Isolated サブネット | RDS（DBサーバ） | 接続不可 |

### 環境別構成

| 環境 | 構成 | 用途 |
|---|---|---|
| 本番（Production） | ＜マルチAZ / シングルAZ＞ | サービス提供 |
| 開発（Development） | シングルAZ | 開発・テスト |

> 構成図については [システム構成図](../../02_システム構成/01_システム構成図.md) を参照。
