# 基盤概要設計_ログ管理編スキル

システムを構成する AWS サービス・アプリケーションから発生するすべてのログについて、
「収集 → 転送 → 保管 → 分析 → 監視」のパイプライン全体を定義するドキュメントを作成・更新する。
ログの種別ごとに保管期間・分析手法・アクセス制御を明確にし、コンプライアンス要件や運用要件を満たす設計を実現する。

## When to Use This Skill

- 「ログ管理設計書を作って」「基盤概要設計_ログ管理編を作って」と言われたとき
- 「ログ管理を整理して」「ログ保管期間を定義して」「ログ収集設計を書いて」と言われたとき
- 「CloudTrailの設計を書いて」「VPC Flow Logsの設計を書いて」「ALBアクセスログの設計を書いて」と言われたとき
- 「S3にログを保管する設計を書いて」「Firehoseでログを転送する設計を書いて」と言われたとき
- 「Athenaでログを分析する設計を書いて」「Splunkのログ分析設計を書いて」と言われたとき
- 既存のログ管理設計書をレビュー・更新するとき

## MECE章構成の設計思想

ログ管理設計を「ログが生まれてから使われるまでのライフサイクル」に沿って分解することで MECE を実現する。

```
1. 設計方針・前提条件        ← なぜこの設計か、誰が管理するか（Why/Who）
2. ログ種別一覧              ← 何のログが存在するか（What/棚卸し）
3. ログ収集設計              ← ログをどこで拾うか（Capture/収集）
4. ログ転送・集約設計        ← ログをどこへどう運ぶか（Delivery/転送）
5. ログ保管設計              ← ログをどこにどれだけ保管するか（Storage/保管）
6. ログ分析設計              ← ログをどう読むか・検索するか（Analysis/分析）
7. ログ監視・アラート設計    ← ログから何を検知するか（Alerting/監視）
8. ログアクセス制御設計      ← 誰がログを見られるか（Access Control/制御）
9. 運用・コスト管理設計      ← どうメンテナンスするか・費用をどう抑えるか（Ops/運用）
```

**MECEの根拠:**
- 2（何がある）≠ 3（どう拾う）: 種別一覧は「存在の把握」、収集設計は「拾い方の定義」
- 3（拾う）≠ 4（運ぶ）: 収集は「ログエージェント・サービス側設定」、転送は「パイプライン設計」
- 4（運ぶ）≠ 5（保管する）: 転送はルーティング、保管は場所・期間・形式の定義
- 5（保管）≠ 6（分析）: 保管は「どこに何日置くか」、分析は「どう問い合わせるか」
- 6（分析）≠ 7（監視）: 分析は人が問い合わせる受動的な行為、監視は条件合致時に自動通知する能動的な行為
- 8（誰が見る）は 6・7 と独立: 分析・監視とは別に IAM/バケットポリシーとして設計

## 作成ワークフロー

### Step 1: テンプレートをコピーして成果物を作成

例として、`templates/基盤概要設計_ログ管理編_template.md` を
`docs/01_要件定義/02_非機能/09_ログ管理/基盤概要設計_ログ管理編.md` にコピーして作業を開始する。

既存ファイルがある場合は上書きせず、差分を確認してから追記・修正する。

### Step 2: 関連ドキュメントの参照

以下のドキュメントを事前に参照し、設計の一貫性を確保する：

| ドキュメント | 参照目的 |
|---|---|
| `01_非機能要求グレード.md` | ログ保管期間・監視間隔・順守法令の確認 |
| `基盤概要設計_クラウドサービス編.md` | 利用 AWS サービス・AWSアカウント設計 |
| `基盤概要設計_ネットワーク編.md` | VPC Flow Logs の有効化可否・S3エンドポイント設計 |
| `基盤概要設計_セキュリティ編.md` | 監査ログ取得要件・CloudTrail 有効化方針・アクセス制御要件 |
| `基盤概要設計_サーバ編.md` | APサーバ・DBサーバのOS/アプリログ種別・取得方法 |

### Step 3: ユーザーへのヒアリング

以下の観点でシステムの特性を確認する：

**ログ種別・収集対象の確認**
- コンプライアンス上、必須となる監査ログの種別（CloudTrail / アプリケーション操作ログ等）
- セキュリティ診断で要求されているログ（VPC Flow Logs 等）
- 運用上必要なログ（APサーバアクセスログ・エラーログ・DB スロークエリ等）

**保管期間の確認**
- 遵守すべき法令・ガイドライン（犯収法 7年 / 個人情報保護法 / PCI DSS 等）によるログ保管期間要件
- RFP・運用ポリシーで規定されたログ保管期間（例: 1年以上）
- コスト面での制約（長期保管コストの許容範囲）

**転送・集約方式の確認**
- ログの集約先（S3 / CloudWatch Logs / SIEM 等）
- リアルタイム性の要件（Firehose によるほぼリアルタイム転送 vs. エクスポートジョブ等）
- 既存の SIEM / ログ管理基盤（Splunk / Datadog / OpenSearch 等）の利用有無

**分析手法の確認**
- アドホック分析のニーズ（AWS Athena による S3 ログの SQL クエリ）
- ダッシュボード・可視化のニーズ（CloudWatch ダッシュボード / Grafana / Splunk 等）
- セキュリティ監視専用の分析基盤（Amazon Security Lake / SIEM）の要否

**アクセス制御の確認**
- ログを閲覧できる担当者・ロール
- ログの改ざん防止要件（S3 Object Lock / CloudTrail ログファイル検証等）

### Step 4: 各セクションの記述

テンプレートのプレースホルダーをヒアリング結果に基づいて埋める。

記述の基本スタイル:
- ログ種別ごとの収集元・収集手段・転送先・保管場所・保管期間を表形式で整理する
- 保管期間は「法令要件（根拠）」と「運用要件（根拠）」のどちらに基づくかを明記する
- 未確定・要調査項目は `> **TODO:**` でマーク
- マネージドサービスを利用する場合など、設定可否に制約がある場合は「ベンダー管理」「お客様管理」を区別する

記述例:

```markdown
### CloudTrail

**収集対象**: AWS マネジメントコンソール / SDK / CLI による全 API 操作ログ  
**有効化範囲**: すべての AWS リージョン（マルチリージョン証跡）  
**保管先**: S3 バケット（`logs-cloudtrail-<account-id>`）  
**保管期間**: 7年（PCI DSS Requirement 10.7 / 犯収法対応）  
**ライフサイクル**:
  - 0〜1年: S3 Standard
  - 1〜7年: S3 Glacier Instant Retrieval（コスト削減）
  - 7年超: 自動削除（S3 ライフサイクルポリシー）
```

### Step 5: レビューチェック

- [ ] すべての AWS サービス・アプリケーションのログが種別一覧に列挙されているか
- [ ] 各ログ種別に保管期間と根拠（法令 / RFP / 運用要件）が記載されているか
- [ ] 転送パイプライン（収集元 → 転送手段 → 保管先）が明確か
- [ ] ログ分析手法（Athena / CloudWatch Logs Insights / SIEM 等）が定義されているか
- [ ] CloudWatch メトリクスフィルターと Alarm による自動監視が定義されているか
- [ ] ログへのアクセス制御（IAM / バケットポリシー / 暗号化）が定義されているか
- [ ] ログの改ざん防止対策（CloudTrail ログファイル検証 / S3 Object Lock）が定義されているか
- [ ] S3 ライフサイクルポリシーによるコスト管理 / 自動削除が定義されているか
- [ ] 非機能要求グレードのログ保管期間要件と整合しているか
- [ ] セキュリティ設計書の監査ログ要件と整合しているか

## テンプレートの構成

テンプレート（`templates/基盤概要設計_ログ管理編_template.md`）は以下のセクションで構成される：

| # | セクション | 主な内容 |
|---|---|---|
| 1 | 設計方針・前提条件 | 設計方針・管理責任区分・準拠法令 |

| 3 | ログ収集設計 | CloudTrail / VPC Flow Logs / ALBアクセスログ / CloudWatch Logs Agent / アプリログ |

| 5 | ログ保管設計 | S3バケット設計 / ライフサイクルポリシー / Object Lock / 暗号化 |
| 6 | ログ分析設計 | Amazon Athena / CloudWatch Logs Insights / OpenSearch / Splunk |
| 7 | ログ監視・アラート設計 | CloudWatch メトリクスフィルター / Alarm / SNS 通知 |
| 8 | ログアクセス制御設計 | IAM ポリシー / S3バケットポリシー / 閲覧権限設計 |
| 9 | 運用・コスト管理設計 | ライフサイクルコスト見積もり / 運用手順 |
