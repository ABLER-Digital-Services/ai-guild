# サーバ設計書スキル

システムを構成するサーバ（APサーバ・DBサーバ・Storageサーバ等）の詳細仕様を定義するドキュメントを作成・更新する。
CPU・メモリ・ディスク・ネットワーク・ソフトウェア・セキュリティ等、各サーバの基盤設計情報を網羅する。

## When to Use This Skill

- 「サーバ設計書を作って」「基盤概要設計_サーバ編を作って」と言われたとき
- 「サーバ仕様を整理して」「サーバ構成を定義して」「サーバスペックを書いて」と言われたとき
- 「APサーバの仕様を書いて」「DBサーバの仕様を書いて」「Storageサーバを定義して」と言われたとき
- 既存のサーバ設計書をレビュー・更新するとき

## 成果物の仕様

以下の格納先・ファイル名・多重作成可否は説明用の例です。実際の配置ルールは対象リポジトリ側の instructions、CONTRIBUTING、README などに従ってください。

| 項目 | 内容 |
|---|---|
| 格納先 | `docs/01_要件定義/02_非機能/04_サーバ/` |
| ファイル名 | `基盤概要設計_サーバ編.md` |
| 多重作成 | 原則1プロジェクト1ファイル（複数サーバを1ファイルに記載） |

## 作成ワークフロー

### Step 1: テンプレートをコピーして成果物を作成

例として、`templates/基盤概要設計_サーバ編_template.md` を
`docs/01_要件定義/02_非機能/04_サーバ/基盤概要設計_サーバ編.md` にコピーして作業を開始する。

既存ファイルがある場合は上書きせず、差分を確認してから追記・修正する。

### Step 2: 定義するサーバを特定する

クラウドサービス設計書（`03_クラウドサービス/基盤概要設計_クラウドサービス編.md`）が存在する場合は先に参照し、
システムを構成するサーバ一覧を確認する。
对象サーバの種別（APサーバ・Storageサーバ・DBサーバ・進入設備等）は、利用プラットフォーム・クラウドサービス履約に従って定義する。
マネージドサービスを利用する場合は、「お客様が設定できる項目」と「ベンダー管理の項目」を検印待延で撮認する。

### Step 3: ユーザーへのヒアリング

サーバごとに以下の観点を確認する：

**CPU構成**
- vCPU 数とクロック（クラウドの場合はインスタンスタイプで決定）
- スケールアップの方針（インスタンスタイプ変更・プラン変更等）

**メモリ構成**
- メモリサイズ（クラウドの場合はインスタンスタイプで決定）
- スワップ領域の要否

**ディスク構成**
- ボリューム種別（SSD/HDD）・容量
- ボリューム用途（ルート・アプリケーション・データ・ログ等）の分離構成
- 暗号化の要否

**ネットワーク構成**
- NIC 数・帯域
- IPアドレス固定/動的の方針
- 接続元制限（IP制限）の設定方針

**ソフトウェア構成**
- OS 種別・バージョン
- ミドルウェア一覧（Webサーバ・APサーバ・DBサーバ・その他）
- ランタイム・言語バージョン

**システム環境**
- 冗長化方針（シングル/マルチ構成）
- バックアップ・リストア方針
- メンテナンスウィンドウ

**ログ管理**
- 取得対象ログ（OS・アプリケーション・アクセスログ等）
- ログ取得方法・格納先
- ログローテーション・保管期間

**クラウド管理**
- 管理ツール・操作手段（マネジメントコンソール/管理ポータル等）
- スケールアップ・スケールアウトの手順
- 起動・停止の手順と制約

**セキュリティ**
- OS/ミドルウェアのパッチ適用責任（自社 or ベンダー）
- アンチウイルス・EDR等のエンドポイントセキュリティ
- 不正アクセス検知（IDS/IPS）の対応

### Step 4: 各サーバセクションへの記述

ヒアリング結果をもとに、サーバごとに以下のフォーマットで記述する。

```markdown
## ○○サーバ

**CPU構成**
- ＜vCPU数・インスタンスタイプ等＞

**メモリ構成**
- ＜メモリサイズ・スワップ設定等＞

**ディスク構成**
- ＜ボリューム名: サイズ・種別・用途＞

**ネットワーク構成**
- ＜NIC・IPアドレス・帯域等＞

**ソフトウェア構成**
- OS: ＜種別・バージョン＞
- ＜ミドルウェア: バージョン＞

**システム環境**
- ＜冗長化・バックアップ・メンテナンス方針＞

**ログ管理**
- ＜取得ログ・格納先・保管期間＞

**クラウド管理**
- ＜管理ツール・操作制約＞

**セキュリティ**
- ＜パッチ適用・エンドポイントセキュリティ・IDS/IPS＞
```

- マネージドサービスを利用する場合は、「お客様が設定できる項目」と「ベンダー管理の項目」を区別して記載する
- インスタンスタイプが未確定の場合は `> **TODO:**` で明示する

### Step 5: レビューチェック

- [ ] 本番環境の全サーバが記述されているか（APサーバ・DBサーバ・Storageサーバ等）
- [ ] 開発環境のサーバも記述されているか
- [ ] CPU・メモリがインスタンスタイプ/スペックと整合しているか
- [ ] ディスク構成がクラウドサービス設計書（`03_クラウドサービス/`）のボリューム定義と一致しているか
- [ ] ソフトウェア構成の OS・ミドルウェアのバージョンが確定しているか（`> **TODO:**` が残っていないか）
- [ ] ログ管理の保管期間が非機能要求グレード（`01_非機能要求グレード/`）の要件と整合しているか
- [ ] セキュリティ項目がセキュリティ要件定義書（`08_セキュリティ/`）と整合しているか
- [ ] クラウドマネージドの場合、設定可否がクラウドサービス設計書と矛盾していないか

## テンプレートの構成

テンプレート（`templates/基盤概要設計_サーバ編_template.md`）は以下のセクションで構成される：

| セクション | 内容 |
|---|---|
| APサーバ（本番） | vCPU・メモリ・ボリューム・ソフトウェア構成 |
| Storageサーバ（本番） | vCPU・メモリ・ボリューム・ストレージ構成 |
| DBサーバ（本番） | vCPU・メモリ・ボリューム・エンジン種別 |
| APサーバ（開発） | 開発環境の構成 |
| DBサーバ（開発） | 開発環境の DB 構成 |
