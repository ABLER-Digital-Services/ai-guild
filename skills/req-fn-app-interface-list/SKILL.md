# インタフェース一覧スキル

開発対象システムと外部システム・外部サービスとの間のすべてのデータ連携を一覧化する。
システム関連図の矢印を具体化し、設計・開発フェーズのインタフェース設計の入力となる。

## When to Use This Skill

- 「インタフェース一覧を作って」「外部連携を整理して」と言われたとき
- システム関連図を作成した後、連携の詳細を定義するとき
- 既存のインタフェース一覧をレビュー・更新するとき

## 成果物の仕様


## IFID採番ルール

| フォーマット | 例 |
|---|---|
| `IF-NNN` | `IF-001`、`IF-002` |

- NNNは3桁ゼロ埋め
- 相手システムごとにまとめて採番する（同じ相手システムのIFを連番で並べる）
- 一度採番したIDは欠番になっても振り直さない

## 各項目の記載ルール

| 列名 | 記載内容 |
|---|---|
| `IFID` | `IF-NNN` 形式の一意ID |
| `IF名` | IFの内容を表す名称（例: 注文データ受信、決済リクエスト送信） |
| `送受信区分` | `送信`（自システム → 相手）/ `受信`（相手 → 自システム） |
| `相手システム` | システム関連図・アクター定義書に記載の外部システム名と一致させる |
| `データ内容` | 連携するデータの種類・内容（例: 注文データ、顧客マスタ、仕訳データ） |
| `方式` | `REST API` / `SOAP` / `ファイル連携（CSV）` / `DB直接連携` / `MQ` など |
| `頻度` | `リアルタイム` / `バッチ（日次）` / `バッチ（月次）` / `バッチ（毎時）` / `オンデマンド` など |
| `備考` | 認証方式・エラーハンドリング・未確定事項など |

## 作成ワークフロー

### Step 1: システム関連図の確認

システム関連図（`03_システム関連図/01_システム関連図.drawio`）の矢印とラベルをすべて洗い出し、IFの候補を列挙する。

### Step 2: 各IFの詳細確認（ヒアリング）

各インタフェースについて以下を確認する：

1. **方式**: API（REST/SOAP）・ファイル連携・DB直接連携など
2. **頻度・タイミング**: リアルタイムか、バッチかを確認。バッチの場合は実行頻度
3. **データ内容**: 何のデータを、どの単位で連携するか
4. **認証方式**: APIキー・OAuth・IP制限など

### Step 3: ドキュメント生成

`templates/interface-list-template.md` を元にドキュメントを生成する。

以下のルールを守ること：
- 相手システム名はシステム関連図・アクター定義書の名称と完全に一致させる
- 同じ相手システムとのIFは連続したIFIDで並べてグループ化する
- 未確定事項は備考欄に `TODO:` で記載する

### Step 4: レビューチェック

- [ ] システム関連図のすべての矢印がIFとして網羅されているか
- [ ] 相手システム名がシステム関連図・アクター定義書と一致しているか
- [ ] 送受信区分の方向が正しいか
- [ ] 方式・頻度が具体的に記載されているか
- [ ] バッチ機能（`F-B-NNN`）との対応が取れているか

## 後続成果物との連携

- **システム関連図** (`03_システム関連図`) — 矢印ラベルとIF名・データ内容を一致させる
- **機能一覧のバッチ機能** (`04_機能一覧`) — バッチ連携はバッチ機能IDと紐づける
- **処理一覧** (`05_処理一覧`) — オンライン処理で外部API呼び出しがある場合はIFIDを備考欄で参照
