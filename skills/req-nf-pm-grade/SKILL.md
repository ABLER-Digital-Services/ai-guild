# 非機能要求グレードスキル

システムの非機能要件を体系的にチェックリスト形式で記述するドキュメントを作成・更新する。
可用性・性能拡張性・運用保守性・移行性・セキュリティ・システム環境の6カテゴリを網羅する。

## When to Use This Skill

- 「非機能要求グレードを作って」と言われたとき
- 「非機能要件を整理して」「可用性の要求を定義して」「セキュリティ要件を整理して」と言われたとき
- 既存の非機能要求グレードをレビュー・更新するとき

## 共有前提

- Agent Skills はリポジトリ横断で共有できる前提で記述する
- skill 本文では、skill 外の特定ディレクトリ構成、固定パス、格納先、ファイル名、多重作成可否を既定しない
- 置き場所や命名などリポジトリ固有の運用ルールは、対象リポジトリ側の instructions、CONTRIBUTING、README などで定義する
- skill では成果物の内容、観点、判断基準、手順の骨子を中心に記述する

## 作成ワークフロー

### Step 1: テンプレートをコピーして成果物を作成

`templates/非機能要求グレード_template.md` をたたき台として使い、実際の格納先・ファイル名・作成単位は対象リポジトリ側のルールに従って決める。

### Step 2: ユーザーへのヒアリング

カテゴリごとに以下の観点でシステムの特性を確認する：

**可用性**
- 運用時間帯（9〜17時のみか、24時間無停止かなど）
- バッチ処理あり/なし、S3等の常時アクセス要否
- 障害時の業務停止許容度（RPO/RTO/RLO）

**性能・拡張性**
- ユーザ数・同時アクセス数（特定ユーザか不特定多数か）
- データ量・増大率の見積もり
- バッチ処理件数と増大率

**運用・保守性**
- バックアップの要否・取得間隔・保存期間
- 監視の要否・監視間隔
- 開発環境・テスト環境の有無

**移行性**
- 新規システムか既存からの移行か
- 移行データ量・移行タイプ

**セキュリティ**
- 遵守すべき法令・ガイドライン（個人情報保護法、PCI DSS等）
- 伝送データ・蓄積データの暗号化要否
- ログ保管期間

**システム環境**
- クラウド利用か否か
- ユーザ・クライアントの規模と種別

### Step 3: チェックリストへの転記

ヒアリング結果を元に、各項目の該当する選択肢に `[x]` を付け、`> ToDo` 部分を実際の根拠・補足説明に書き換える。

書き方の例：
```markdown
### 運用時間（通常）

バッチ稼働は1日1回を想定。オンライン機能は存在しない。

- [ ] 規定無し
- [ ] 定時内（9時～17時）
- [x] 夜間のみ停止（9時～21時）
- [ ] 1時間程度の停止有り（9時～翌朝8時）
- [ ] 若干の停止有り（9時～翌朝8時55分）
- [ ] 24時間無停止
```

### Step 4: レビューチェック

- [ ] 全カテゴリのすべての項目に選択肢が記入されているか
- [ ] `> ToDo` が残っている項目がないか（未記入の確認）
- [ ] 相互に関連する項目（RPO/RTO/RLO、稼働率など）の整合性が取れているか
- [ ] セキュリティで法令・ガイドラインを選んだ場合、対応するセキュリティ項目レベルが適切か

## テンプレートの構成

テンプレート（`templates/非機能要求グレード_template.md`）は以下の6セクションで構成される：

| セクション | 主な項目例 |
|---|---|
| 可用性 | 運用時間・計画停止・RPO/RTO/RLO・稼働率 |
| 性能・拡張性 | ユーザ数・データ量・バッチ件数・各増大率・CPU/メモリ利用率 |
| 運用・保守性 | バックアップ・監視・開発/テスト環境・保守契約 |
| 移行性 | 移行期間・並行稼働・データ移行タイプ |
| セキュリティ | リスク分析・暗号化・ログ管理・不正監視 |
| システム環境 | ユーザ数・クライアント数・耐震・設置スペース |
