# 通知一覧スキル

システムからユーザー・管理者などに対して送信されるすべての通知（主にメール）を一覧化する。

## When to Use This Skill

- 「通知一覧を作って」「メール通知を整理して」と言われたとき
- システムが送信する通知の網羅性を確認したいとき
- 既存の通知一覧をレビュー・更新するとき

## 各項目の記載ルール

| 列名 | 記載内容 |
|---|---|
| `宛先` | 通知を受け取る対象者の説明（例: 新規登録ユーザー、注文をしたユーザー、システム管理者）。メールアドレスなど具体的な値は記載しない。アクター定義の名称と必ずしも一致しなくてよい |
| `契機` | 通知が送信されるトリガーとなるイベント（例: 会員登録完了時、パスワード変更時、注文確定時） |
| `通知内容` | 通知で伝える内容の要旨（例: 登録完了のお知らせと初回ログイン案内、注文確定内容と配送予定） |

## 作成ワークフロー

### Step 1: 通知の洗い出し（ヒアリング）

以下の観点でユーザーに確認する：

1. **ユーザー向け通知**: 登録・変更・購入・状態変化など、ユーザーの操作・状況に応じて送られる通知
2. **管理者向け通知**: エラー発生・申請・異常検知など、運営担当者・管理者へ送られる通知
3. **定期通知**: 月次レポート・リマインダーなど、スケジュールで送られる通知

### Step 2: ドキュメント生成

`templates/notification-list-template.md` を元にドキュメントを生成する。

以下のルールを守ること：
- 宛先はメールアドレスや固有名詞ではなく、**誰の立場の人か**を説明的に記載する
- 契機は「〜時」「〜した場合」の形で統一する
- 通知内容は送信される情報の要旨を体言止めで記載する
- 送信チャネル（メール・SMS・プッシュ通知など）が複数ある場合は備考列を追加して区別する

### Step 3: レビューチェック

- [ ] 処理一覧の各処理に紐づく通知が漏れていないか
- [ ] バッチ機能（エラー・完了）の通知が漏れていないか
- [ ] 宛先が具体的なメールアドレスになっていないか
- [ ] 契機が「〜時」の形で統一されているか

## 後続成果物との連携

- **処理一覧** (`05_処理一覧`) — サーバサイド処理の完了・エラー時に通知が発生するケースは処理一覧の備考欄から参照
- **バッチ機能一覧** (`04_機能一覧`) — バッチ完了・エラー通知はバッチ機能IDと紐づけて管理
