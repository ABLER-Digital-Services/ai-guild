
## 段階的な進め方

### Phase 1. 土台をつくる

最初にやるべきことは、投稿ルールと自動判定の最小セットです。

- リポジトリの目的と対象読者を明文化する
- 資産カテゴリごとの配置ルールを決める
- Pull Request テンプレートを用意する
- 所有者ルールを決める
- ブランチ保護を設定する
- 最低限の CI を入れる

この段階では、レビューの厳しさよりも、全員が同じ形で投稿できることを優先します。

### Phase 2. AI レビューを本格運用する

次に、Pull Request に対して複数観点の AI レビューを走らせます。

- 変更種別の自動判定
- カテゴリ別レビュープロンプトの切り替え
- セキュリティと安全性チェック
- ドキュメント品質チェック
- 重複資産の候補提示
- 必要に応じた修正提案コメント

理想は 1 本の万能レビューではなく、用途別の小さいレビュー担当を複数走らせることです。

例:

- instruction reviewer
- agent safety reviewer
- documentation consistency reviewer
- taxonomy reviewer
- metadata reviewer

### Phase 3. 採用しやすい導線をつくる

利用者にとって重要なのは、投稿より先に「見つけやすいこと」です。

- カテゴリ別の目次を生成する
- タグと難易度で絞り込めるようにする
- 用途別のおすすめ一覧を出す
- 社内ユースケース別の導線をつくる

awesome-copilot が強いのは、資産の量だけでなく、探索性が高い点です。社内版でもここを早めに整えるべきです。

### Phase 4. 貢献を見える化する

この段階で、コミュニティ性を高める仕掛けを入れます。

- 貢献者一覧の自動更新
- 月次の新規貢献サマリ生成
- 人気資産ランキングの公開
- カテゴリ別の貢献分布レポート
- レビュー対応速度の可視化

単純な件数ランキングだけだとノイズが多いので、次のようなスコア設計が現実的です。

- merged PR 数
- 採用された資産数
- 利用回数や参照回数
- 継続メンテナンス回数
- レビュー協力数

## AI 自動レビューの設計方針

AI 自動レビューは、次の 3 層で考えるのが安全です。

### Layer 1. 形式チェック

- フォルダ配置
- 必須メタデータ
- frontmatter や見出し構造
- リンク整合性
- ファイル命名規約

### Layer 2. 内容チェック

- 既存資産との重複
- 内容の曖昧さ
- 指示の危険性
- 実行前提の不足
- 社内標準との不整合

### Layer 3. 運用チェック

- 所有者レビューが必要か
- セキュリティ確認が必要か
- breaking change の可能性があるか
- 目次や索引の再生成が必要か

ポイントは、AI に最終判断を丸投げしないことです。AI は判定材料を増やし、人間はマージ責任を持つ構図にします。

## 会社版として追加したい仕掛け

awesome-copilot の単純コピーではなく、社内版では次を差別化ポイントにすると強いです。

### 利用申請より利用標準化

使う前に申請させるのではなく、最低限安全に使える状態を標準で提供する。

### 資産の信頼ラベル

各資産に次のような状態を持たせる。

- experimental
- reviewed
- approved
- deprecated

### 対象読者ラベル

- beginner
- team-standard
- advanced
- admin-only

### 適用範囲ラベル

- company-wide
- product-specific
- language-specific
- workflow-specific

これがあると、読むだけの人でも採用判断しやすくなります。

## 最初の 4 週間でやるとよいこと

### Week 1

- 目的、対象、投稿単位を定義する
- カテゴリ構成を決める
- 最小のレビューと保護ルールを決める

### Week 2

- Pull Request テンプレートを整備する
- 所有者ルールを整備する
- AI レビューの初版を GitHub Actions で動かす

### Week 3

- 目次生成やメタデータ検証を追加する
- 貢献者集計の仕組みを入れる
- ラベル設計を確定する

### Week 4

- 社内に公開して試験運用する
- 実際の PR を数本流してレビュー精度を調整する
- 採用しにくい導線を修正する

## 最初に決めるべき意思決定

開始時点で曖昧にしない方がよい論点です。

- どこまでを社内標準として承認対象にするか
- AI レビューの指摘を必須にする範囲
- Team メンバーの直接編集をどこまで許すか
- 利用実績の計測方法をどう定義するか
- 貢献スコアを公開する範囲

## 推奨する最初の実装順

1. リポジトリ骨格の作成
2. ブランチ保護と所有者ルールの導入
3. Pull Request テンプレート導入
4. AI 自動レビュー初版の導入
5. 目次生成とメタデータ検証
6. 貢献者可視化の自動化
