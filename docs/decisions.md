# 未決定事項

このファイルは、ai-guild の構築を進める上で、実装前に確認したい論点をまとめるためのものです。

## 1. CODEOWNERS の対象

現時点の決定:

- 既定オーナーは @jun-shiromizu

推奨:

- リポジトリ全体に 1 つの管理 Team を置き、資産カテゴリごとに追加オーナーを重ねる

決まるとできること:

- CODEOWNERS 導入
- レビュー要求の自動化

次に見直すこと:

- Team 運用に移る段階で、個人オーナーから Team オーナーへ切り替える

## 2. ブランチ保護の厳格度

決めたいこと:

- main への直接 push を完全禁止にするか
- 自動レビューと人間レビューを何件必須にするか

推奨:

- main への直接 push は禁止
- 必須チェック通過
- 人間レビュー 1 件以上

決まるとできること:

- GitHub の保護ルールを具体化

## 3. AI レビューの実装方式

現時点の決定:

- 初版は GitHub 標準寄りで始める
- まずは GitHub 上で完結するレビュー運用を優先する
- Actions ベースの専用レビューは後から必要分だけ足す

推奨:

- 初期は GitHub 上で完結しやすい構成を優先し、必要なら後から Actions ベースの専用レビューを追加する

決まるとできること:

- ワークフロー初版の実装

次に見直すこと:

- GitHub 標準レビューで不足する観点が明確になったら、カテゴリ別の専用レビューを追加する

## 4. 貢献の可視化範囲

現時点の決定:

- ランキングや重み付きスコアは入れない
- README とドキュメント上の軽量な可視化から始める
- all-contributors を採用候補とする

推奨:

- まずはリポジトリ内で見える軽量な一覧から始め、数値の扱いに問題がなければ拡張する

決まるとできること:

- 貢献者一覧や月次集計の自動化

次に見直すこと:

- Bot 導入可否を確認し、運用可能なら all-contributors を正式導入する

決まるとできること:
